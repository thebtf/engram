# v6.4.14

## Fixed

### Codex plugin MCP server failing with MODULE_NOT_FOUND

With v6.4.13 installed, Codex sessions logged:

```
MCP server stderr (node): Error: Cannot find module
'C:\...\plugins\cache\engram-marketplace\engram\6.4.13\${CLAUDE_PLUGIN_ROOT}\scripts\run-engram.js'
```

Codex does **not** interpolate `${CLAUDE_PLUGIN_ROOT}` in plugin `.mcp.json`
args — the placeholder reached node verbatim, joined to the server `cwd`
(the plugin root), and the wrapper never started. Claude Code has the exact
opposite constraint: it interpolates `${CLAUDE_PLUGIN_ROOT}` but does not
resolve relative args against the plugin root, so a single shared config
cannot satisfy both consumers.

Verified by live bisect on codex-cli 0.136.0 and Claude Code:

| args form | Codex | Claude Code |
|---|---|---|
| `${CLAUDE_PLUGIN_ROOT}/scripts/run-engram.js` | MODULE_NOT_FOUND | ✔ Connected |
| `./scripts/run-engram.js` (cwd `.` = plugin root) | ✔ 19 engram tools | ✘ Failed to connect |

The fix ships per-consumer MCP configs:

- Root `.mcp.json` (referenced by `.codex-plugin/plugin.json`) uses the
  relative entrypoint `./scripts/run-engram.js` with `cwd: "."`.
- New `claude/.mcp.json` (referenced by `.claude-plugin/plugin.json` via
  `"mcpServers": "./claude/.mcp.json"`) keeps the interpolated
  `${CLAUDE_PLUGIN_ROOT}` entrypoint. Claude Code's manifest `mcpServers`
  path replaces the root default, so each consumer loads only its own
  config (verified live: exactly one engram server entry in `claude mcp list`).

Both configs forward `ENGRAM_URL` / `ENGRAM_TOKEN` via `env_vars` and contain
no `env` block (the v6.4.13 `${user_config.*}` regression guard now covers
both files).

## Upgrade notes

Update/reinstall the plugin from the marketplace in both Claude Code and
Codex. No server-side change, no config change required on workstations that
already set `ENGRAM_URL` / `ENGRAM_TOKEN`.
