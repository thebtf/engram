# v6.5.0 — Milestone F complete, hybrid retrieval, upstream decoupling

Release date: 2026-06-12

## Summary

v6.5.0 ships the complete Milestone F feature set (TG1–TG6: privacy scopes,
node taxonomy, ranking rationale, crystallization candidates, write-lint
two-phase protocol, governance operations), the W-program work items (W2
crystallization wiring and `purge_project`, W3 hybrid FTS+vector retrieval,
W4 scope-bypass fixes), upstream decoupling refactors (U1–U3), and four
production fixes.

**All new subsystems default to OFF.** Flag-OFF behavior is byte-identical to
v6.4.15 — the tested compatibility contract. Activate features per-deployment
via environment flags described below.

---

## What's New

### Milestone F: TG1 — Privacy scopes

Adds a four-tier `privacy_scope` column to the `memories` table:

| Scope | Visibility |
|-------|------------|
| `private` | Issuing workstation only |
| `project` | Any workstation in the same project (default) |
| `shared` | Any authenticated workstation |
| `global` | All workstations, including cross-project retrieval |

Retrieval paths (session-start injection, store list, FTS search) enforce scope
when `ENGRAM_VNEXT_F_ENABLED=true`. Flag-OFF: scope column exists but is not
filtered, preserving existing retrieval behavior.

### Milestone F: TG2 — Knowledge node taxonomy (13 types)

The knowledge graph now supports typed nodes. Thirteen node types:
`concept`, `entity`, `process`, `decision`, `pattern`, `skill`, `tool`,
`artifact`, `role`, `constraint`, `goal`, `event`, `unknown`.

The `graph` MCP tool gains:
- `add_node` action (creates a typed node)
- `node_type` filter on `get_edges`
- `source_type`/`target_type` discriminators on `add_edge` (default `memory`)

Active when `ENGRAM_VNEXT_F_ENABLED=true`. Backward-compatible: empty
discriminators default to `memory` for v6.2.x edge records.

### Milestone F: TG3 — Explainable rerank + ranking rationale

`recall_memory` can now return a `rationale` object per result. Activate with
`explain=true` in the call. Fields returned:

- `recency_days` — age of the memory in days
- `confidence` — stored confidence value
- `citation_count` — how many times the memory has been cited
- `tier` — current lifecycle tier (`episodic`, `semantic`, etc.)
- `substring_match` — whether the query appeared verbatim in content
- `filters_applied` — list of active filter names

The store-level `ListWithFilters` method is also new, accepting
`confidence_min`, `include_superseded`, and `limit` options.

### Milestone F: TG4 — Crystallization candidates

Memories that pass the crystallization gate are staged as `pending` candidates
before promotion to the main memory store. Operators and agents can review,
promote, reject, or mark candidates as superseded.

New MCP tools (active when `ENGRAM_VNEXT_F_ENABLED=true`):

| Tool | Description |
|------|-------------|
| `list_candidates` | List pending crystallization candidates for a project |
| `promote_candidate` | Promote a candidate to a full memory |
| `reject_candidate` | Reject a candidate (preserves content for audit) |
| `supersede_candidate` | Mark a candidate as superseded by another memory |

### Milestone F: TG5 — Write-lint two-phase protocol

`store_memory` under `ENGRAM_VNEXT_F_ENABLED=true` runs a two-phase write:

1. **Phase 1** — validates content, detects conflicts with existing memories,
   returns conflict signals and a single-use resolution token.
2. **Phase 2** — caller presents the token to complete the write. Token is
   consumed atomically (concurrent duplicate submits are rejected).

A redaction middleware layer runs before Phase 1. Redaction rules are loaded
from `ENGRAM_REDACTION_RULES_PATH` at server startup (see flag table below).

`dry_run=true` is now accepted by `store_memory`, `promote_candidate`,
`bulk_promote`, `bulk_delete`, and `bulk_supersede`. A dry run validates and
returns a preview without writing.

### Milestone F: TG6 — Governance operations

Bulk operations now create snapshots before executing, enabling rollback.

New MCP tools (active when `ENGRAM_VNEXT_F_ENABLED=true`):

| Tool | Description |
|------|-------------|
| `list_snapshots` | List bulk-op snapshots (filterable by project, date) |
| `rollback_snapshot` | Roll back a snapshot to undo a bulk operation |
| `pin_snapshot` | Pin a snapshot to prevent automatic retention pruning |
| `redaction_rules_status` | Show loaded redaction rules and their match counts |
| `bulk_promote` | Bulk-promote multiple candidates (supports `dry_run`) |
| `bulk_delete` | Bulk-delete memories by ID list (supports `dry_run`) |
| `bulk_supersede` | Bulk-supersede memories by ID list (supports `dry_run`) |

Export bundles: `governance.Export()` produces a deterministic ZIP archive with
`manifest.json` (SHA-256 checksums per entry), `content/`, `edges/`, and
`candidates/` directories. Optional `.bin` embedding files with
`IncludeEmbeddings=true`.

Snapshot retention: snapshots older than `ENGRAM_SNAPSHOT_RETENTION_DAYS`
(default 30) are pruned by the sleep cycle.

### W2: Crystallization pipeline wiring

When `ENGRAM_CRYSTALLIZATION_ENABLED=true`, session-end processing runs the
crystallization pipeline and stores extracted decisions as
`epistemic_type=decision, tier=episodic` memories. Requires
`ENGRAM_VNEXT_ENABLED=true` for the audit trail.

Audit trail now fires on: memory create, delete, supersede, edit, sleep cycle
promotion, and sleep cycle demotion. Audit log retention: 90 days (pruned by
`runRetentionCleanup`).

### W2: `purge_project` admin operation

```
admin(action="purge_project", project="<name>", confirm="<name>")
```

Deletes all memories, crystallization candidates, knowledge edges, and vectors
for the named project. Double-entry confirmation (`confirm` must equal
`project`) is required. Returns a receipt with counts of deleted rows. Active
when `ENGRAM_VNEXT_ENABLED=true`.

### W3: Hybrid retrieval read path

`recall_memory` and `recall(action="similar")` under `ENGRAM_VNEXT_ENABLED=true`
use a three-tier hybrid pipeline:

| Tier | Method | Notes |
|------|--------|-------|
| Tier 0 | Exact text match | Fast path for literal query strings |
| Tier 1 | Vector (FindSimilar) | Cosine similarity via pgvector HNSW |
| Tier 2 | FTS (SearchFTS) | PostgreSQL tsvector BM25 |

Results from all three tiers are fused with Reciprocal Rank Fusion (RRF) and
re-scored with FR-C4 recency/confidence weighting. The `explain=true` parameter
(TG3) annotates each result with its fusion score breakdown.

`recall(action="explain")` now forwards to `recall_memory(explain=true)` under
the flag.

### U1–U3: Upstream decoupling

Contract-driven test rewrites across nine suites (U1), behavior-preserving
infrastructure rewrites (U2), and `pkg/models` rewrites (U3). These changes
make the codebase auditable and independently attributable without altering
any observable behavior. The dead `pkg/models/scoring.go` file (zero callers)
was deleted.

## Environment Flags

All flags default to `false`. Set to `"true"` in the server environment.

| Flag | Default | What it enables |
|------|---------|-----------------|
| `ENGRAM_VNEXT_ENABLED` | `false` | Master vNext gate. Enables: retention cron, `purge_project` admin action, hybrid retrieval (`recall_memory` / `recall similar` / `recall explain`), audit trail. |
| `ENGRAM_VNEXT_F_ENABLED` | `false` | Milestone F gate (requires `ENGRAM_VNEXT_ENABLED=true` for full feature set). Enables: privacy scope enforcement on all retrieval paths, knowledge node taxonomy, TG3 rationale/filters, crystallization candidates + MCP tools, write-lint two-phase protocol, governance MCP tools, bulk-op tools, snapshot rollback, redaction layer. |
| `ENGRAM_LIFECYCLE_ENABLED` | `false` | Enables the sleep cycle (tier promotion/demotion) and `tier_filter` param on `recall_memory`. |
| `ENGRAM_CRYSTALLIZATION_ENABLED` | `false` | Enables session-end crystallization pipeline. Requires `ENGRAM_VNEXT_ENABLED=true` for audit trail. |
| `ENGRAM_SNAPSHOT_RETENTION_DAYS` | `30` | Integer. Days before bulk-op snapshots are pruned by the sleep cycle. Applies when `ENGRAM_VNEXT_F_ENABLED=true`. |
| `ENGRAM_REDACTION_RULES_PATH` | (none) | Path to a JSON redaction rules file. When absent, redaction is a no-op. Loaded once at server startup. Active when `ENGRAM_VNEXT_F_ENABLED=true`. |

### Recommended activation sequence for a fresh Milestone F deployment

```
ENGRAM_VNEXT_ENABLED=true
ENGRAM_LIFECYCLE_ENABLED=true
ENGRAM_VNEXT_F_ENABLED=true
ENGRAM_CRYSTALLIZATION_ENABLED=true
```

Apply in this order after running DB migrations (see below). Do not set
`ENGRAM_VNEXT_F_ENABLED=true` before `ENGRAM_VNEXT_ENABLED=true` — F-flag
paths that call the audit trail will silently no-op without the master gate.

## Flag-OFF Compatibility Statement

When all vNext flags are unset (the default), v6.5.0 is byte-identical in
observable behavior to v6.4.15:

- `tools/list` returns the same tool names and schemas.
- `recall`, `store_memory`, `admin`, and all other existing tools behave
  identically.
- The new DB columns (`privacy_scope`, `tier` default change, etc.) exist in
  the schema but do not affect query results.
- No new background goroutines start.

This contract is the basis of the v6.5.0 test suite: every new code path is
guarded by a flag check, and the flag-OFF branch is the existing v6.4.15
implementation path.

## Production Fixes Included

These fixes shipped within the v6.5.0 development cycle and are present
regardless of flag state:

- **SSE broadcast wedged-client panic and blocking** — a client whose write
  stalled past the 2s write timeout could panic the broadcaster (send on
  closed channel) or block every subsequent broadcast. Dead-client reports now
  flow through a buffered channel that is never closed; `Broadcast` returns
  within the write timeout regardless of stuck clients, and stalled clients
  are cleaned up on the next broadcast pass.
- **Clock-skew in `List` / `SearchFTS` / `GetByIDs`** — DB queries now use
  SQL `NOW()` for timestamp comparisons, not Go `time.Now()`. Fixes incorrect
  recency ordering when server and DB host clocks diverge.
- **Synchronous self-update backup rollback** — atomic rollback on error;
  no partial state left on disk.
- **`outFile.Close` error on success path** — `Close` error is now checked
  after a successful write, preventing silent data loss on flush failure.
- **W4: Privacy-scope bypass closure (P1–P3)** — three retrieval paths that
  could return memories above the caller's scope ceiling under
  `ENGRAM_VNEXT_F_ENABLED=true` are now correctly filtered.

## Upgrade Notes

1. **No breaking changes.** Flag-OFF behavior is byte-identical to v6.4.15.
   Upgrade without setting any new flags to get only the production fixes.

2. **DB migrations auto-run.** No manual schema changes are needed. The server
   applies all new migrations on startup before serving traffic.

3. **Flag activation order.** When enabling Milestone F features:
   set `ENGRAM_VNEXT_ENABLED=true` before `ENGRAM_VNEXT_F_ENABLED=true`.
   The F-flag relies on the master gate for audit trail wiring.

4. **Tier default change** (`131_tier_default_episodic`). This migration runs
   unconditionally and changes the DB-level default for new `memories` rows from
   `semantic` to `episodic`. Existing rows are not affected. If you have
   application code that INSERTs memories without an explicit `tier` value and
   expects `semantic`, add the explicit value.

5. **Redaction rules.** If you set `ENGRAM_REDACTION_RULES_PATH`, the file is
   loaded once at server startup. A restart is required to reload updated rules.
   The file format is a JSON array of rule objects; see
   `internal/redaction/doc.go` for the schema.
