# Engram v7.0.19

Browser-session credential protection (native tracker item 535).

## Fixed

- Separate public session-management handles from private `engram_auth` cookie credentials. Session JSON, Access lists, user drilldown, revoke selectors and browser-auth audit correlation use the public handle; a handle cannot authenticate as a cookie. Existing authorization, cookie expiry, logout and revocation remain in place.
- Add transactional migration `190_browser_session_public_handle`: backfill one `sessions.public_handle` column, enforce its unique lookup index and retain an old-writer compatibility trigger. Preserve private cookie IDs, primary keys, lifecycle fields and historical audit rows. Browser-specific Operator Code audit correlation uses the same safe handle without changing private tab authorization or SDK/agent session identity.
- Project scoped browser-session credential material out of historical in-memory log snapshots and live SSE responses without deleting buffered records. Text-query matching uses the safe projected message/raw JSON; snapshot query filtering precedes the latest-lines limit. With no query, snapshot keeps its fast level-filtered tail selection and projects only the selected entries before returning them. SDK/agent correlation and unrelated harmless diagnostics remain available.

## Upgrade notes

- Use the ordinary release channels. The owner's Unraid repository remains `ghcr.io/thebtf/engram:latest`; do not replace it with a digest or version pin. Keep the existing auth mode and preservation/recovery inputs; no new startup variable or credential provisioning is required.
- Refresh an old Access view before Revoke. Private cookie IDs are no longer accepted as management selectors; credential or unknown selectors return 404 without mutation. Use the public handle returned by the current session list.
- Migration 190 refuses destructive rollback. Compatibility with older SQL writers preserves data; it does not make an older credential-exposing server a safe behavioral rollback. Retain the normal migration, recovery and rollout checks.
- This is scoped browser-session projection, not general secret detection or proof that historical logs never exposed credentials. Source-built synthetic HTTP/JSON/SSE evidence is not installed acceptance; verify the delivered server and its ordinary consumer path separately.
