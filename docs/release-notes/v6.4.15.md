# v6.4.15

## Root cause: Codex 0.139 env forwarding loss

Codex 0.139 stopped forwarding `[shell_environment_policy.set]` values to
plugin MCP server children. This is an undocumented behavioral change; see
openai/codex#24401. There is no supported env-injection path for plugin MCP
servers in Codex (`plugins.<plugin>.mcp_servers.<server>` accepts only
`enabled`/`tools` fields). Prior versions of the engram plugin relied on
`ENGRAM_URL`/`ENGRAM_TOKEN` appearing in the plugin subprocess environment via
`shell_environment_policy.set` — that path is now silently broken for Codex
≥ 0.139.

## Fix: config file credential fallback

The plugin wrapper (`run-engram.js`) and hooks (`lib.js`) now use a JSON
config file as the final step in the credential resolution chain. The chain
in priority order:

| Priority | Source |
|---|---|
| 1 | `ENGRAM_URL` / `ENGRAM_TOKEN` environment variables |
| 2 | `CLAUDE_PLUGIN_OPTION_server_url` / `CLAUDE_PLUGIN_OPTION_api_token` (Claude Code userConfig) |
| 3 | `ENGRAM_CLAUDE_USERCONFIG_URL` / `ENGRAM_CLAUDE_USERCONFIG_TOKEN` (legacy aliases) |
| 4 | Config file: `$ENGRAM_CONFIG_FILE` → `<pluginData>/config.json` → `~/.engram/config.json` |

Config file format:

```json
{
  "server_url": "http://your-server:37777",
  "api_token": "engram_<32hex-keycard-from-dashboard>"
}
```

## Security

- On POSIX: file is `chmod 0600` (owner read/write only).
- On Windows: file lives in the user profile directory; NTFS ACLs inherited from
  the parent directory (`~/.engram/`) already restrict access to the owner
  account. No `icacls` call is made.
- Token values are never written to logs or stderr. The startup diagnostic
  reports `config_file=present(<path>)` or `config_file=missing(<path>)` but
  never the token value.

## Go client change: not needed

`cmd/engram/main.go` reads `ENGRAM_URL`/`ENGRAM_TOKEN` via `os.Getenv` after
the JS wrapper has already resolved and set them in `process.env`. The Go
binary inherits the fully-resolved values as normal process environment, so no
Go-side change is required. This is verified by tracing the exec flow:
`run-engram.js` calls `process.env.ENGRAM_URL = serverURL` and
`process.env.ENGRAM_TOKEN = token` before `spawnSync(binaryPath, ..., { env:
process.env })`.

## Upgrade notes

For Codex users on 0.139+: create `~/.engram/config.json` with your server URL
and worker keycard (the same values previously in `config.toml`). On POSIX:
`chmod 600 ~/.engram/config.json`. Restart Codex / open a new thread.

For Claude Code users: no change required — `settings.json` env still works and
is higher priority than the file. The config file is available as a universal
fallback if needed.
