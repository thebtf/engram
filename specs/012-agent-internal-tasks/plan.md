## Summary

An ordinary caller creates one existing issue, safely retries it, finds it on a later filtered page, refines its revision, records an outcome comment, and resumes from a fresh authorized connection. The [caller contract](contracts/issues.md) is the normative accepted request/response/error shape. The source extends the existing IssueStore transaction owner and adapters; it does not add a tracker or network service. Source/fixture proof is not completion of this journey.

**Depth**: D1 inside the existing issue boundary: durable cross-session callers and data need explicit concurrency, privacy and migration rules, but no new subsystem or ADR. The accepted requirement, owner, violating events, preserved state and future path proof are recorded in contracts, data-model and quickstart rather than separate assurance documents.
