# Operator-console parity ledger

There is no mockup-to-Nuxt code generator. The curated public contract is
`design/operator-console/PROMOTION-MANIFEST.json`; its hashes and design version are
the authority, not the private `.od` workspace or an old `DESIGN.md` stamp.

`npm run parity` verifies every promoted hash, the 15 route + 2 frame mapping, runtime
targets, and ledger uniqueness. A `synced` row must cite stored route-specific visual
evidence and the current manifest version. `drifted` is an honest unfinished state and
is reported without pretending the route matches; `npm run parity -- --strict` rejects
acknowledged drift for release/production-readiness gates.

G1 records every row as `drifted` from the 2026-06-21 audit. No structural code review
may change that to `synced`: only accepted Chrome evidence can do so.

The 2026-10-11 shell repair adds recovery through the existing normal cookie-user login
and logout contracts; it does not promote a new auth or visual model. README.md owns its
session/credential/context invariants. The shell remains drifted until the integrated
candidate has ordinary-user real-API Chrome login, expiry, truthful role/noauth, failed
logout and responsive keyboard evidence. Source seam checks and a build are not that proof.

The bounded R3 follow-up repairs project context-search recovery and diagnostic status,
not the visual model. Literal memory/document tasks retain the canonical project and
operator query; technical request evidence is secondary and the footer no longer claims
a database engine. Diagnostic capability loss is not a server outage or authentication
verdict. Original R3 auth/content/return/mobile evidence remains historical input, not a
new proof of these bytes. Memory audit and independent multiple-type selection are not
closed by status-filter AND or this source check. Root acceptance and Main release stay
open for the narrow changed-consumer proof on the existing isolated Chrome target.

The F1 client migration follows Main's mandatory canonical `project` audit query without
changing the route or DTO. It clears old history on scope/session changes and rejects
late or mismatched responses; denial is not empty history. This does not prove the server
privacy repair or legitimate audit events. Existing committed F3/F4 behavior stays intact;
Root acceptance/Main release still require the coherent backend and narrow real-consumer
proof. Standalone multiple-type selection still requires its actual backend interface.

The agreed Main multi-type interface adds visible memory choices and literal document
type chips: any selected type (OR), AND existing criteria within exact canonical/privacy
scope before count/page; documents choose latest versions before type filtering.
Arrays survive query/page/detail/reauth return. No principal-kind or status-AND substitute,
invented document enum, CSV parser, page-local filter or ignored type control is used.
Source/compiled-consumer/build proof is not real SQL/privacy/Chrome acceptance. The
historical1002 wrapper is preparation only and must bind the final committed type build.

The raw-URL edge repair strictly decodes each `docType` entry at the existing navigation
boundary and retains corruption as an explicit invalid choice across reauth. It does not
ban valid percent literals, Unicode or comma names, and never turns corruption into a
successful empty or unfiltered read. The earlier14/build1045 remains historical proof;
the changed edge has its own bounded RED/GREEN and build binding, not Chrome acceptance.
